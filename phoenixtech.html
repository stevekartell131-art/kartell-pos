// problem statement

Manual billing doesn't scale past a handful of clients

Small ISPs and hotspot operators in Kenya run subscriber billing by hand — creating MikroTik user accounts one at a time, chasing payments over phone calls, and disconnecting non-payers with no audit trail.

There's no self-service path for a customer to pay and get connected without a technician in the loop. Every new subscriber is a manual task; every renewal is a manual task; every non-payment is a manual disconnect someone has to remember to do.

// subscriber lifecycle

One state machine, driven by two APIs

Every account moves through the same five states. M-Pesa Daraja confirms the money; RouterOS confirms the connection. PHOENIXTECH is the layer that keeps them in sync.

01 · SIGNUP

Subscriber registers

Phone, address, plan and NAS assignment captured

02 · PAYMENT

STK push via Daraja

Callback confirms payment or falls back to polling reconciliation

03 · PROVISION

RouterOS API call

PPPoE/hotspot user created, bandwidth queue applied

04 · EXPIRY

Grace period starts

Expiry-warning notification queued for SMS

05 · SUSPEND

Access disabled

Account suspended on RouterOS until next payment

// core scope, v1

Five modules, one billing state

Scoped directly from the v1 PRD. Nothing here is speculative — each module maps to a section operators will actually touch.

5.1

Subscriber management

  • CRUD on name, phone, address, NAS assignment
  • Plan assignment — speed tier, cap, price, duration
  • Status: active / expired / suspended / pending
5.2

Billing & payments

  • M-Pesa Daraja STK push
  • Callback handling auto-extends subscription
  • Manual cash/bank entry for edge cases
  • Invoice and receipt generation
5.3

MikroTik integration

  • RouterOS API connection per NAS
  • Auto create/enable/disable on payment events
  • Bandwidth profile synced to simple queue
  • Configurable grace period on expiry
5.4

Admin dashboard

  • Active vs. expired subscriber counts
  • Revenue by day / week / month
  • Expiring-in-24h follow-up list
  • Router/NAS health status
5.5

Subscriber self-service

  • Login by phone number
  • View plan status, initiate renewal
  • Expiry-warning and payment SMS
—

Out of scope, v1

  • Multi-router load balancing
  • Reseller / agent commissions
  • Native mobile app
